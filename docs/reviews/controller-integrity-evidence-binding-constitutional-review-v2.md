# Controller integrity evidence binding: independent review v2

**Verdict: REVISE**

## Scope and independence

This follow-up review assesses the revised `controller-integrity-evidence-binding` design for issues #161/#162, with focus on the prior review findings, fixed `.secrets.baseline` eligibility, #160 governed-identity equivalence, CI admission and replay, validation time-of-check/time-of-use handling, and legacy migration. It was conducted as a fresh-context review task, separate from the design author; this basis is an accountability statement, not an authentication or identity claim. No design, controller, milestone state/history, or prior review artifact was changed. No tests were run because this review evaluates the design checkpoint, not an implementation.

## Assessment

The revision resolves the prior material findings at the design level. It fixes residue eligibility to one exact path, makes capture part of initialization, and excludes only the captured residue with explicit type/mode/content and provenance checks. It defines #160’s only permitted equivalence as proof that the registered artifact-only descendant reconstructs the same governed identity, while requiring fresh CI for B. It closes caller-input and generic `ci_observed` success paths, defines a complete check inventory and fail-closed replay binding, and requires explicit quarantine of unbound legacy validation evidence. The validation design’s evidence snapshot, final identity recomputation under generation-checked lock, and conflict behavior provide a reasonable local race boundary; Git ref movement remains non-atomic and is identified as a conflict-producing limitation.

## Material finding

**The CI workflow that produces the admitted check names is not pinned to a trusted behavior identity.** The revision fixes the required check inventory to the `ci.yml` job names `Scan for secrets`, `Validate`, and `Test`, and requires an expected workflow identity at the observed commit. It does not define that expected identity as a trusted digest/version or say that modifying the workflow itself blocks CI admission pending separate review. A governed commit can change `.github/workflows/ci.yml` while preserving those job names and return successful but materially weakened checks; exact SHA, complete names, and successful conclusions would then describe execution of the changed workflow, not the intended validation policy. The workflow currently defines those names in [ci.yml](/home/tullas/github/vss/.github/workflows/ci.yml:11) and [ci.yml](/home/tullas/github/vss/.github/workflows/ci.yml:271), while the design’s inventory and “expected workflow identity” are at [design](/home/tullas/github/vss/docs/reviews/controller-integrity-evidence-binding-design.md:40). Add a closed trust rule for workflow identity, such as requiring the exact controller-approved workflow digest or making any relevant workflow change ineligible to produce passed CI until separately reviewed. Job names alone do not establish the workflow behavior.

The remaining reviewed constraints appear adequately bounded in the design: `.secrets.baseline` is the sole eligible residue and the existing `.local` exception stays distinct ([design](/home/tullas/github/vss/docs/reviews/controller-integrity-evidence-binding-design.md:28), [design](/home/tullas/github/vss/docs/reviews/controller-integrity-evidence-binding-design.md:56)); #160 reuse requires exact artifact-only reconstruction ([design](/home/tullas/github/vss/docs/reviews/controller-integrity-evidence-binding-design.md:38)); CI cannot advance source binding, conflict is latched, and generic checkpoint injection is prohibited ([design](/home/tullas/github/vss/docs/reviews/controller-integrity-evidence-binding-design.md:42), [design](/home/tullas/github/vss/docs/reviews/controller-integrity-evidence-binding-design.md:86)); legacy receipts are quarantined until explicit migration ([design](/home/tullas/github/vss/docs/reviews/controller-integrity-evidence-binding-design.md:44)); validation rechecks exact evidence identity before append and handles later source movement as conflict ([design](/home/tullas/github/vss/docs/reviews/controller-integrity-evidence-binding-design.md:36), [design](/home/tullas/github/vss/docs/reviews/controller-integrity-evidence-binding-design.md:42)). These are design commitments and still need implementation and adversarial tests.
